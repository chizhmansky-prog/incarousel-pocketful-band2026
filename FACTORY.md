## Reuse the development factory

1. Create a fresh BAND room and fresh result repository. Register four seats with
   separate identities, attach each actual coding runtime, and install the generic
   `mandates/` before dispatching the problem. Fill Harness and Model with reality.
2. Connect the room's pull receivers to an existing dispatcher. Bind each receiver
   exclusively to its seat and workspace. The dispatcher performs native research,
   planning, author implementation and independent review; a receiver only transports.
3. Have the lead carry full specifications and mandates at initial dispatch. Every
   handoff includes full requirements, exact source revision, immutable source bytes,
   commands/results and a stop condition. Relay an author's canonical output verbatim
   through its actual seat, rather than attributing coordinator prose to that author.
4. Keep author implementation and review separate. Execute specification-derived
   positive, negative, state-atomicity, replay and regression probes against the delivered
   image. Bind source and served assets before accepting reports. Retain failures and
   route a bounded repair to the same author through the dispatcher.
5. Freeze four stage folders and ordinary commits. Save the genuine full console
   export, verify offline submission gates and a fresh public clone, then retain receipt.

The general contracts work with other specifications. This repository documents the
configured integration rather than distributing the private Head service or provider
credentials. An equivalent native dispatcher and authenticated worker runtimes are
prerequisites. This reuse limitation is explicit.
